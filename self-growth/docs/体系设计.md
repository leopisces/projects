# 成长账本 · 体系设计（定稿）

> 最后更新：2026-11-08 · 状态：v1 已定稿，开始实现

## 1. 这个系统是什么

一个**纯正向**的自我成长记录与激励系统。做了一件对成长有用的事 → 用一句话描述 → 大模型判定维度与分数 → 记入成长值，等级与连续天数随之推进。

- **只增不减**：成长值不会因为享乐、休息、犯错而扣减
- **不做兑换**：没有奖励商店，分数本身就是回看和升级的依据
- **负向行为只标记、不扣分**：熬夜、刷手机超时会被识别出来打上标记，用于阶段性回看，不影响成长值

### 为什么不做惩罚 / 兑换

惩罚会让人开始隐瞒记录，兑换会让记录变成"刷分买玩具"。两者都会把系统从"看清自己"推向"应付系统"。本系统的价值在于**如实**，所以一切设计优先保证记录的真实和轻便。

## 2. 五个维度（已定：方案 B）

一次记录**只归一个主维度**。

| 维度 | 图标 | 覆盖范围 |
|------|------|----------|
| 身体 body | 🫀 | 运动、睡眠、饮食、体检、康复 |
| 心智 mind | 🧠 | 学习、阅读、思考、技能练习、理解 |
| 情绪关系 heart | 🫶 | 情绪调节、家人朋友、社交、陪伴与求助 |
| 创造产出 craft | 🔨 | 写代码、写作、做出作品、解决真实问题（对外） |
| 秩序 order | 🧭 | 环境、习惯、时间、财务、流程与资源整理 |

### 2.1 判定边界（模型打分必须遵守）

**心智 vs 创造产出** — 看有没有对外的产出物
- 读书 50 页 → 心智
- 读完写成笔记发出去 → 创造产出
- 弄懂一个概念 → 心智；拿它解决了实际项目问题 → 创造产出

**身体 vs 秩序** — 一个管生理，一个管运转
- 跑步、早睡、体检 → 身体
- 整理桌面、记账、排周计划 → 秩序
- 按时吃三餐 → 身体（生理需求优先）

**情绪关系 vs 秩序** — 一个管人，一个管事
- 跟朋友深聊、和家人和解、靠运动缓解焦虑 → 情绪关系
- 文件归档、订日程 → 秩序

**秩序 vs 其他** — 秩序只记"摆正了结构和资源"，不记具体进展
- 推进一步代码 → 创造产出
- 把 git 分支理清 → 秩序

### 2.2 不设的维度

**「精神 / 意义」不单独成维度**。它容易变成万能标签，且难以和另外五维分离。意义感按落点归位：
- 帮了别人、想清楚自己要什么 → 情绪关系
- 做出了东西 → 创造产出

### 2.3 不加维度，加轴

每条记录带一个**挑战等级**轴（对"现在的我"而言的难度）：
- 舒适区内 ×1.0
- 略超舒适区 ×1.3
- 明显吃力 ×1.6

## 3. 打分规则（已定：固定分 + 难度自评）

### 3.1 基础分 1–20

| 区间 | 强度 | 例子 |
|------|------|------|
| 1–4 | 微小 | 收拾桌子、散步 10 分钟 |
| 5–9 | 标准 | 学习 30 分钟、运动一次、读完一章 |
| 10–14 | 扎实 | 攻克难题、写完一篇输出、一次深度对话 |
| 15–20 | 里程碑 | 完成一个项目、跑完长距离、连续 30 天 |

**最终得分 = round(基础分 × 挑战系数)**

### 3.2 上限（防刷分）

- **同类上限**：同一 `kind`（模型归一化出的 2–6 字类别，如「跑步」「深度学习」）一天最多 **3 次**计分；第 4 次起仍写入记录，但标记「勤勉 · 不计分」，成长值不增加
- **单日软提示**：当日累计 > 60 分时只提示一句「今天是不是记得太乐观了」，不拦截、不清零
- **不补记**：只能记当前时刻，不能回填过去日期（保证数据反映真实节奏）

### 3.3 负向标记（已定：只标记不扣分）

命中熬夜、通宵、刷手机 / 短视频、整天躺平、暴饮暴食等，标记 `negative: true`，成长值 +0，维度照常判定（便于统计"哪一维被挤掉了"）。

## 4. 等级曲线（已定：递增）

第 n 级所需累计成长值：

```
R(n) = 100 × (n−1) × n / 2
```

| 等级 | 累计值 |
|------|--------|
| Lv2 | 100 |
| Lv3 | 300 |
| Lv4 | 600 |
| Lv5 | 1,000 |
| Lv10 | 4,500 |
| Lv20 | 19,000 |

按每天 20 分估算，约两个月到 Lv5。

## 5. 记录流程

```
一句话描述
   ↓
大模型打分（维度 / kind / 基础分 / 挑战系数 / 负向 / 一句理由）
   ↓
预览卡：确认 / 修改 / 撤销
   ↓
写入成长值（同类上限与负向规则在此生效）
```

### 5.1 为什么要一句话

给模型打分需要上下文，顺带解决了"要不要写反思"的取舍——**描述本身就是反思的最小单位**。一句话就够，不强制长篇。

### 5.2 打分失败怎么办

不阻塞记录。LLM 不可用时（无 Key / 请求失败 / 超时）自动降级为**本地规则打分**：关键词匹配维度 + 语气词判断难度，标注 `source: 'rule'`，界面上显示为「本地估算」，事后可在流水里改。

### 5.3 规则文档（唯一事实来源）

打分口径**不写在代码里**，而是写在 `public/rulebook.md`：

- 应用启动后第一次打分时用 `fetch` 读取（`src/rulebook.js`），作为 system 提示词下发
- 改规则 = 改文档，不用重新打包；模型每轮都拿到最新版
- 「我的 → 评分规则」可直接在页面上编辑，覆盖版存在 `settings.rulebookOverride`，可一键恢复内置版
- 文档内包含：输出 JSON 契约、判定流程、五维边界、基础分锚点表、挑战系数、负向清单、kind 同义词合并表、few-shot 示例，以及用户自留的「补充例子」区
- 拿不到文档时（离线/路径变了）退到 `rulebook.js` 里的精简兜底提示词，不会卡死记录

## 6. 数据模型

```js
{
  version: 2,
  settings: {
    unit: 'GV',              // 成长值单位名
    startValue: 0,           // 起始成长值
    dailyGoal: 20,           // 每日目标
    dailySoftCap: 60,        // 单日软提示线
    sameKindCap: 3,          // 同类单日计分次数上限
    useLLM: true,
    apiBase: 'https://ark.cn-beijing.volces.com/api/v3',
    apiKey: '',
    model: '',
    rulebookOverride: '',   // 自定义评分规则（空 = 用 public/rulebook.md）
  },
  entries: [
    {
      id, ts,
      text: '今天刷了两小时数学题，终于弄懂 σ 代数的意义',
      dimension: 'mind',
      kind: '深度学习',
      base: 8,
      challenge: 1.0,
      points: 8,
      negative: false,
      counted: true,
      reason: '纯理解性投入，有明确突破点',
      source: 'llm' | 'rule',
    }
  ],
}
```

存储：网页版 `localStorage['self-growth.v2']`，写入节流 120ms 并即时落盘（`pagehide` / 页面隐藏 / 原生 `pause`）。
APK 额外走 **SQLite 双写**（`src/storage-native.js`）：表 `entries(id,ts,day,dimension,data)` + `kv(key,value)`，写入 `executeSet(..., true)` 单事务整表替换；启动时 `hydrateNative()` 从库回灌，库还空就用现有数据播种。
原因：Android WebView 的 localStorage 不可靠，清缓存/系统回收会连数据一起没（实测过）。
导出/导入仍为 JSON 备份。

## 7. 界面结构

| 页面 | 内容 |
|------|------|
| 记录 | 目标条（含正向/负向笔数与净得分）→ **快捷记账**六宫格（一点入账 + 可撤销）→ 一句话输入 → 打分预览（可改维度/基础分/挑战系数）→ 今日列表（撤销、删除）；超软提示线提示，同类超上限记「勤勉·不计分」 |
| 流水 | 按日分组，显示维度色点、时间、分数、AI 理由、出处；可改维度与分数、可删除；可只看负向 |
| 日历 | ① 月历热力网格：每格显示当日得分，绿深浅=日目标完成度（4 档），红点=当天有负向，今天蓝框；② 六宫格月汇总（本月得分/记分天数/日均/最高一天/达标天数/负向次数）；③ **本月账本**：按天倒序一行一天（日期+周几、笔数、当日合计），展开看当天每条明细与当日合计 |
| 统计 | ① 能力图：五维雷达，可切本周/近30天/近90天/全部，**实线本期 vs 虚线上期**，附各维数值与环比；② 近 14 天柱状；③ 等级曲线进度；④ 负向统计 |
| 我的 | 评分规则（查看/编辑/恢复内置/复制）、模型配置、记账设置（单位/起始值/目标/软提示线/同类上限）、数据导出导入与清空 |

## 8. 技术栈

Vue 3 + Vite，纯前端 PWA，数据存 localStorage，无后端无账号。

- LLM 调用为 OpenAI 兼容 `/chat/completions`，baseURL / Key / model 全部可配
- **CORS 已解决**：浏览器直连厂商 API 会被拦（DeepSeek 不放行 Origin），因此 `vite.config.js` 把 `/llm-proxy` 反代到 `https://api.deepseek.com`，dev 与 preview 都生效；前端 `apiBase` 填 `/llm-proxy/v1` 即同源调用
- 默认凭据放 `src/config.local.js`（**gitignored**，含 key），由 `src/local-config.js` 用 `import.meta.glob` 软加载——文件不存在时不影响 build；也可在「我的」里手填，优先级是「设置里填的 > 本地配置 > 空」
- ⚠️ build 后 Key 会内联进 `dist/` 的 js：dist 不入库，也不要公开部署到公网；需要公网访问就换成自己的反代并在那把 Key 藏起来
