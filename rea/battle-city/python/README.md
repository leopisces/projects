# 坦克大战 Python 复刻版

Namco《Battle City》(1985) 的 Python 重制。**图形、关卡地图、调色板、敌方配置全部实时读自原版 ROM**，不是手画素材。

```
python/
├── bc_rom.py            ROM 解析层（CHR/调色板/关卡表/敌方配置）
├── audio.py             音频层（播 ROM 合成的 WAV）
├── battle_city.py       游戏主体
├── run.bat              双击启动
├── sprite_atlas.png     精灵图鉴（核对 tile 编号用）
├── shot_stage1.png      第 1 关截图
└── shot_stage9.png      第 9 关截图
```

## 运行

```powershell
cd C:\Users\Leopisces\Desktop\projects\rea\battle-city
pip install pygame            # 只需一次
python python/battle_city.py --rom battle_city.nes
```

ROM 会自动在 `python/`、项目根、桌面上找 `battle_city.nes` / `坦克大战.nes`；
也可以用 `set BATTLE_CITY_ROM=D:\path\xxx.nes` 指定。

### 操作

| 键 | 作用 |
|---|---|
| 方向键 / WASD | 移动 |
| 空格 / J | 开火 |
| Enter / P | 暂停 |
| Esc | 退出 |

### 参数

```powershell
--scale 4          放大倍率（默认 3）
--stage 9          直接从第 9 关开始
--atlas            只生成精灵图鉴
--mute             静音
--shot out.png     无窗口渲染一帧并保存（--frames 300 控制帧数）
```

## 哪些是"原汁原味"的

| 项目 | 来源 | 说明 |
|---|---|---|
| **关卡地图** | ROM `$F07A` | 36 条 × 91 字节，13×13 nibble 流，与上游反汇编字节级一致 |
| **地形图形** | ROM CHR (PT1) | 砖 `$0F`、钢 `$10/$20`、水 `$12`、冰 `$21`、森林 `$22` |
| **坦克 / 老鹰图形** | ROM CHR (PT0) | 玩家 `$F1+4×朝向`，敌方 `$B9+4×朝向`，老鹰 `$C8/$CA/$C9/$CB` |
| **调色板** | ROM `$D565` | 背景 9 组 × 16 字节，取 index 0（原版游戏中调色板） |
| **精灵调色板** | ROM `$D555` | 4 组，玩家用 SP0（黄褐），敌方按类型取 SP1/2/3 |
| **敌方构成** | ROM `$E578` | 每关 4 种类型各多少辆，合计固定 20 辆（例：第 1 关 18 基本 + 2 快速） |
| **敌方出场顺序** | ROM `$E4EC` | 每关前 4 个出场的类型字节 |
| **出场间隔** | ROM 公式 | `$BE − 关卡×4` 帧，与 `SpawnEnemy` 一致 |
| **HUD 文字** | ROM CHR (PT1) | 数字 `$30-$39`、字母 `$41-$5A` 直接取原版字库 |
| **地形属性** | ROM `$DACB` | 每格 4 个 tile 的映射表 |
| **得分** | ROM `$E8BA` | 100 / 200 / 300 / 400 |

## 音效与音乐

音频不是采样，是 `tools/sound.py` 逆向音序引擎后用 APU 合成器生成的 WAV，放在 `../sound/`。
游戏在 `audio.py` 里按事件触发：

| 事件 | 文件 | 原版音序槽 |
|---|---|---|
| 关卡开始 | `bgm_stage_start.wav` | 1,2,3 |
| 暂停 | `jingle_pause.wav` | 0 |
| 过关 | `jingle_result.wav` | 27 |
| Game Over | `jingle_gameover.wav` | 24,25,26 |
| 玩家开火 | `seq_15.wav` | 15 |
| 打砖墙 / 打钢墙 | `seq_12 / seq_13` | 12 / 13 |
| 坦克中弹 | `seq_07.wav` | 7 |
| 装甲坦克被击 | `seq_14.wav` | 14 |
| 老鹰被毁 | `seq_11.wav` | 11 |
| 道具出现 / 拾取 | `seq_09 / seq_06` | 9 / 6 |
| 加命 | `seq_10.wav` | 10 |
| 履带声 / 撞墙 | `seq_17 / seq_16` | 17 / 16 |

没有 `sound/` 目录时会静默降级，游戏照常能玩。用 `--mute` 可关闭音频。

## 按 ROM 逐条移植的部分

以下都不是"感觉像"，而是从反汇编里找地址后照着写的：

| 子系统 | ROM 地址 | 说明 |
|---|---|---|
| 敌人目标阶段 | `$DE72` | `$84>>2`、`$84>>3` 与帧计数 `$0A` 比较 → 冲基地 / 随机 / 追玩家 |
| 换向条件 | `$DC7C` | 必须 X、Y 都在 8px 网格 + `PRNG & $0F == 0`（1/16） |
| 撞墙反应 | `$DD11` | `PRNG & $03 == 0` → 25% 掉头`EOR $02`，否则只翻履带帧 |
| PRNG | `$D44D` | `r = r*7 + $0A + zp[$10++]` |
| 帧计数 | NMI `$D43C` | `$0B++`，每 64 帧 `$0A++` |
| 子弹 4 探测点 | `$E604` | A/C 命中即停弹，B/D 只连带破砖 |
| 闪光车 | `$E393` | 剩余数 = 3 / `$0A` / `$11` 时标记，每 16 帧闪 |
| 道具掉落 | `$E8BE` | 只有闪光车掉；位置和类型都用 PRNG 取 |
| 履带动画 | `$DD29` | `$B0 ^= $04` 两帧交替 |
| 开局幕布 | `$CC90`/`$CCB2` | 上下各 16 行灰砖展开后收拢 |
| 重生计时 | `$DE46` | `$0108 = $0D` 出生动画，`$0106 = $D8` |
| 暂停 | `$C214` | `$F5` 从 28 降到 1，音乐降速而非静音 |

## 哪些是近似的

诚实说明，这几处不是从 ROM 逐字节翻译的：

- **敌方 AI**：原版是「阶段分层的目标选择 + 网格对齐概率转向」（`$DE72` SpeedCtrlMove）。这里用的是简化版：按概率转向 + 4 关后倾向追玩家，其余压向基地。
- **子弹与爆炸**：程序化绘制（3×3 白点 / 同心圆）。原版用精灵 tile，编号未定位。
- **道具图形**：用 `$81 + type×4`（依据 `PowerupSpriteDraw $E23B` 的说明），未经视觉验证。
- **坦克 4 个朝向的对应关系**：确认 `$B9/$BD/$C1/$C5` 是同一辆坦克的 4 个朝向，但**哪个是↑哪个是→没有视觉验证**。如果方向看起来不对，改 `bc_rom.py` 里的 `ENEMY_BASE` / `PLAYER_BASE` 偏移即可。
- **冰面滑行、护盾时长、道具持续时间**：原版有精确帧数（如护盾 `$62`），这里是手感调的。
- **只支持 1P**。原版 2P 需要一整套双人输入/复活逻辑。

## 核对精灵编号

`sprite_atlas.png` 是全部 64 个 16×16 精灵块，每块左上角标了 tile 基址（`$00`、`$04`…）。
`$B9` 那一块就是敌方坦克、`$F1` 是玩家坦克、`$C8` 是老鹰。
如果游戏里坦克/道具长得不对，对着这张图把 `bc_rom.py` 顶部的常量改掉就行 —— 所有编号都集中在那里。

## 已实现的玩法

- 13×13 场地，砖墙按 8px 粒度逐块破坏（子弹沿弹道挖洞）
- 钢墙挡弹（玩家 3 级可破）、水挡车不挡弹、森林遮车、冰面滑行
- 基地老鹰 + 周围砖墙，被打爆即 Game Over
- 20 辆敌方坦克分 4 类：基本 / 快速 / 火力 / 装甲（4 血）
- 同屏上限 4 辆，3 个出场点轮换，出场有闪烁动画
- 玩家 3 条命，重生有短暂无敌
- 6 种道具：护盾 / 冻结 / 铁锹 / 星星（升级，3 级可破钢）/ 手雷 / 加命
- 击杀第 4、11、18 辆时掉落道具，闪烁 20 秒
- 分数、过关、Game Over 画面，暂停
