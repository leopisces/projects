# 魂斗罗1 (Contra) 逆向笔记 —— 声音引擎

**目标**：把这个 ROM 的音乐/音效引擎逆向清楚，并把曲目数据导出成可听的音频 + 音符事件。

**被测文件**：`魂斗罗1.nes`（用户桌面，不入库）

| 项 | 值 |
|---|---|
| 大小 | 393,232 字节 |
| md5 | `7e9b74e6b2f0f4ca91d2e32fce356867` |
| iNES 头 | `4e 45 53 1a 08 20 40 00` → PRG 8×16KB、CHR 32×8KB |
| mapper | **4 (MMC3)**，无电池 |
| 向量 | NMI=`$F889` RESET=`$F80D` IRQ=`$F8E1` |

> ⚠️ 这不是零售版《Contra (U)》（那个是 mapper 2 / UNROM，128KB PRG + 128KB CHR、262,160 字节）。
> 本文件 CHR 是零售版的两倍且有 MMC3，**地址与零售版不能直接对照**，下面所有结论都只对本文件成立。

## 1. bank 结构（从 PRG 首字节观察到的事实）

每个 PRG bank 的头一个字节是 bank 标记，之后往往跟着一张"本 bank 内指针表"：

| bank | 首字节 | 映射地址 | 内容 |
|---|---|---|---|
| 0 | `$10` | `$8000` | 指针表 `$8007 $8068 $8100 $80A9 …` |
| **1** | `$12` | `$8000` | **声音引擎 + 全部音乐数据**（详见 §2） |
| 2 | `$14` | `$8000` | 指针表 `$801D $8050 $8087 $80BD …` |
| 3 | `$16` | `$8000` | 一串 CHR bank 号 `02 03 04 05 12 13 14 15 0E 0F 39 1C 1D 1E`（⚠️ 推断：CHR 银行查找表） |
| 4 | `$18` | `$8000` | `00 20 6B 00 8B 30 33 34 …`（⚠️ 未分析） |
| 5 | `$1A` | `$8000` | 代码（`A5 F5 29 30 D0 6B …`） |
| 6 | `$1C` | `$8000` | 代码（`B5 BA 15 C8 D0 33 …`） |
| 7 | `$1E` | `$C000`/`$E000` | 固定 bank：重置/NMI/IRQ、主循环 |

## 2. 声音引擎（bank 1）

代码区约 `$8000-$8AFF`，数据区 `$8B00-$BFFF`。

| 地址 | 作用 | 证据 |
|---|---|---|
| `$8717` | 引擎复位（`$8719` 主体：清 6 个通道、`$4015`/`$4000`/`$4004`/`$400C` 静音） | `JSR $8717` 后跟 `LDA #$30 / STA $4000` |
| `$8758` | 只静音不复位 | `LDA #$30 / STA $4000/$4004/$400C`、`$4001/$4005 = $7F` |
| `$877B` | 停止当前音效（清 `$010A`/`$0123`，`JSR $866F`） | — |
| `$87A2` | **请求播放入口**：`STA $0122`（请求 id），`CMP #$82` 越界忽略，`CMP #$7F` → `$88DA`（另一条路径） | 见 §3 |
| `$8920` | **音效/音乐命令表**：3 字节一项 `[flags][ptr_lo][ptr_hi]` | 见 §3 |
| `$85F2` | `AND #$0F` 后做移位累加（周期/音量换算） | — |
| `$861D` | `LDY #0` + 通道指针 → `($E0)` | — |
| `$862A` | **跳转命令**：`INY` 读指针+1 送 `$0112,X`，+2 送 `$0118,X` | — |
| `$8637` | 分通道选择（X≥1 时切到 `$0123`） | — |
| `$865F` | 初始化：`$4015=$0B`、`$4008=0` | — |
| `$86C6` | ⚠️ 命令处理子程序跳转表（`X=通道号*2`） | `$8492 LDA $86C6,X / JMP ($00E4)` |
| `$89F3` | `JMP ($019D)` —— 主循环里另一处间接跳转（⚠️ 未分析） | — |

### 2.1 通道 RAM 变量（X = 0..7）

| 地址 | 含义 |
|---|---|
| `$0112`/`$0118` | 当前序列数据指针 lo/hi |
| `$0124` | 通道标志位（`$08` 子流程、`$10` 颤音、`$40` …） |
| `$0100` | 当前音符剩余时值 |
| `$0154` | 基础时值（`$0100` 由它按 `$015A` 之类的倍率算出） |
| `$0132` | 移调 |
| `$014E` | 音量高 4 位 / 低 4 位 = 包络变速 |
| `$0136` | 包络号（低 4 位）；`$0178` 包络指针，`$80` = 无包络 |
| `$015A` | 颤音参数 |
| `$0172`/`$010C` | 当前周期 lo/hi（写 `$4002/X`、`$4003/X` 用） |
| `$0148` | 循环/重复计数 |
| `$0142` | 当前音高 |
| `$0106` | 每通道当前 id（优先级比较用） |
| `$0120` | 当前处理的通道号暂存 |
| `$0122` | 当前请求的 id |
| `$010A`、`$0123` | 音效状态 |

### 2.2 命令表结构（`$8920`）

```
ptr = $8920 + 3*id
flags, lo, hi = ptr[0..2]
channel = flags & 7            ; 只有该通道会被启动
if id < $0106[channel]: 放弃   ; 低优先级不打断高优先级
$0112[ch], $0118[ch] = lo, hi
$010C[ch] = $F8
$0100[ch] = 1
```

基址 `$8920` 是从代码字节里"偷"出来的：`$880A LDA $8717`（`$20`）+ `$880D LDA $8718`（`$89`）⇒ `$8920`。

| `$03` | `18` | `$9247` |
| `$04` | `01` | `$9247` |

### 2.3 序列数据样例

`id=$05` @ `$9256`：

```
9256: 22 30 60 0e 50 0e ff
```

`id=$07`/`$08` @ `$9268`：

```
9268: 21 f0 10 a2 d3 8a 53 57 43 27 33 27 fe 2b 6c 92 e3 8a 63 57 53 27 43 27 fe 2c 78 92 f3 8a … ff
```

可见规律：`$21`、`$22`、`$FE`、`$FF` 反复出现；`53 57`、`43 27`、`33 27` 是成对的字节，第二字节可能是时值；`a2 d3 8a` 是"命令 + 16 位地址"的形态（地址落在 `$8Axx`，正好是引擎区，像是指向子程序/子流程）。⚠️ 命令语义尚未定案。

### 2.4 包络表

bank1 头部 `$8001` 起是 8 个一组指向 `$9Bxx` 的指针；`$9B21` 起的数据形如：

```
9B21: 05 06 07 06 05 04 03 ff   03 04 03 02 ff   07 06 05 04 03 02 01 00 00 00 02 02 ff …
```

值是 0-7、`$FF` 结尾 ⇒ **音量包络表**（⚠️ 推断：每个通道的包络集，`$FF` 结束）。

## 3. 已经确定的做法

单靠手工解码命令流太容易出错，计划用**无头引擎**跑数据：

1. 6502 模拟器（`tools/cpu6502.py`）
2. harness（`tools/play_sound.py`）：内存=RAM + bank1 + 固定 bank，APU 写操作记事件
3. 合成（`tools/apu.py`）：按 NES APU 规则出 WAV
4. 事件日志 → 音符事件（周期 → 音名）→ 可核对乐谱
